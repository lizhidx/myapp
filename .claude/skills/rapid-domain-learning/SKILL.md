# 快速认知跨越：四步法

核心信念：真正的门槛不是智力，而是**是否有勇气修正自己的认知**。
本 skill 的目标不是替用户给出结论，而是帮用户搭好一个**全面、严谨、可校正**的判断框架，并最终落到可执行的判断上。

一个议题的最终结论往往需要**多轮论证**，而且事态会随时间发展。所以本 skill 把研究组织成一个**持续追踪的研究项目**，而不是一次性分析。

---

## 研究生命周期（多轮）

```
首轮：建档轮（完整四步）
   ↓ 存入研究档案
更新轮 #2、#3 …（每当有新事态、触发信号或到了约定时间）
   ↓ 每轮追加到档案，判断随证据逐步修正
结案轮（结果揭晓或用户决定结束）
   ↓ 对照全部历史判断做校准复盘
```

| 轮次类型 | 何时进入 | 做什么 |
|---|---|---|
| **建档轮** | 新议题，没有研究档案 | 完整执行阶段0–5，建立研究档案 |
| **更新轮** | 已有档案，且出现新事态、修正触发点被触发、到了约定的复盘时间，或用户想再深挖一轮 | 执行"更新轮工作流"（U0–U5），在原档案上追加 |
| **结案轮** | 结果已经揭晓，或用户决定停止追踪 | 执行"结案轮工作流"（C1–C3），复盘整条判断轨迹 |

**进入 skill 时先判断轮次**：问用户（或查找）是否已有这个议题的研究档案。有就走更新轮或结案轮，没有就走建档轮。不要对已有档案的议题从阶段0重新开始。

### 研究档案（跨轮次的记忆）

多轮研究依赖一份**研究档案**，结构见 [templates/dossier.md](templates/dossier.md)。规则：

- **存放位置**：能写文件的环境（如 Claude Code）里，保存为 `research/<议题简称>/dossier.md`，每轮结束时更新。不能写文件的环境里，每轮结束时把完整档案放在一个代码块里输出，请用户保存，下一轮开始时粘贴回来。
- **只追加，不改写历史**：判断记录、证据日志、修正记录都只能追加新条目。过去的判断即使错了也要保留原样，这是之后复盘和校准的依据。当前状态（当前判断、当前光谱、当前触发点）可以更新，但旧值要记入历史。
- **每条证据和数据都带日期和来源**，方便判断它是否已经过时。

### 多轮论证的纪律

1. **不锚定**：每一轮都要重新看反方的最新论点，不能只找支持上一轮结论的新证据。
2. **不过度反应**：一条新闻通常不该让判断大幅摆动。每次调整都要说明调整幅度和理由：这条信息有多可靠？它是新信息，还是早已被市场和民调消化的旧信息？它属于信号还是噪音？
3. **调整要可追溯**：每次判断变化都要写明"从 X% 调到 Y%，因为……"，并关联到证据日志里的具体条目。
4. **区分事态变化和认知变化**：判断改变，可能是因为世界变了（新事件），也可能是因为之前想错了（新认识）。两种都要如实记录，后者尤其重要，这正是修正认知的勇气。
5. **来源会被验证**：随着事态发展，光谱里专家的预测会被现实检验。表现持续差的来源要降权甚至移出光谱，表现好的要升权。

## 建档轮工作流（必须严格按顺序执行）

```
阶段0 定题 → 阶段1 破茧 → 阶段2 光谱 → 阶段3 概念 → 阶段4 闭环 → 阶段5 存档
   │关卡0      │关卡1      │关卡2      │关卡3      │关卡4
   └─用户确认──┴─用户确认──┴─用户确认──┴─用户确认──┴─用户确认
```

每个阶段都有**必须产出物**和**退出关卡**。关卡没通过，就不能进入下一阶段。下面的防跳步铁律同样适用于更新轮和结案轮。

### 防跳步铁律

1. **一次回复只做一个阶段。** 不要在同一条回复里写下一阶段的内容，也不要提前透露结论（比如在阶段1就说"综合来看 A 更可能赢"）。
2. **每条回复开头都显示进度条**，格式固定：
   ```
   【议题简称 · 第N轮 · 建档/更新/结案】
   进度：✅0 定题 → ▶️1 破茧 → ⬜2 光谱 → ⬜3 概念 → ⬜4 闭环 → ⬜5 存档
   ```
   ✅ 已完成，▶️ 进行中，⬜ 未开始。更新轮和结案轮用各自的阶段名（U0–U5、C1–C3）。
3. **每个阶段结尾必须做关卡自检**：逐条列出本阶段的必须产出物，标注 ✅ 或 ❌。有 ❌ 就先补齐，不能进入下一阶段。
4. **关卡需要用户回应才能放行。** 自检通过后，以固定问句结束本条回复，等用户回复"继续"、提出追问或修改意见。用户追问时，留在当前阶段处理完，再重新问一次。
5. **用户要求跳步时**（例如一上来就问"直接告诉我谁会赢"）：
   - 说明跳步的风险：没有可信来源和概念基础，结论可能只是在放大已有偏见；
   - 提供两个选项：(a) 完整流程；(b) **快速版**：每个被跳过的阶段压缩成 3–5 行的最小产出，但仍按顺序逐一列出，不能省略；
   - 用户坚持只要某一阶段的内容时，可以只做那一阶段，但必须在回复里明确写出"缺少阶段X的哪些前提，因此本结论的可靠性受限于……"。阶段4例外：它至少需要阶段2的来源矩阵和阶段3的核心概念，缺了就先用快速版补上。
6. **中途回退是允许的。** 后面阶段发现前面有缺陷（比如阶段4发现某个关键概念没讲清楚），明确说"回到阶段X补充"，补完后再回来，进度条同步更新。
7. 环境中有任务清单工具（如 TaskCreate / TaskUpdate）时，在每轮开始时为本轮各阶段各建一个任务，随进度更新状态。
8. **每轮必须以存档阶段结束**（阶段5 / U5 / C3）。没有更新研究档案的一轮，等于没做，下一轮无法接上。

### 运行模式：互动模式 / 自主模式

- **互动模式**（默认）：按上面的关卡逐阶段等待用户确认。
- **自主模式**：用户表示"你自己去查、直接告诉我结论"，或不希望每一步都参与时使用。规则：
  - 一次回复里按顺序完成本轮所有阶段，不等用户确认（铁律第1、4条在这个模式下不适用）；
  - **防跳步要求照常**：每个阶段的必须产出物都要完成。依赖用户回答的项目（初始看法、自检回答、理解检验）记为"用户未提供"；关卡自检由 Claude 自己执行，结果写进档案；
  - 回复按阶段顺序给出每个阶段的要点，最后给出结论，详细内容放进研究档案；
  - 结论之后告诉用户，可以对任何一个阶段提出质疑或补充，Claude 会回到那个阶段修改。

### 回测（模拟时钟）

用户要求"把时钟拨回某天"检验方法时：
- 在阶段0设定**模拟日期**，档案里同时记录真实日期和模拟日期。每轮只使用发布日期不晚于模拟日期的信息，每条证据都标注发布日期，日期不明的不用。
- 不检索、不阅读结果类信息，直到结案轮。
- 如实写**污染声明**：模型训练数据里可能包含模拟日期之后的信息；搜索结果里如果混进了截止日之后的内容，要记录下来，并说明没有作为证据使用。
- 更新轮按模拟时钟往前推进（例如每个关键初选之后一轮），最后用真实结果打分。

### 通用规则（所有阶段适用）

- 涉及近期事件、实时数据（民调、赔率、价格等）或具体人物的最新观点时，优先联网搜索核实，并标注信息日期。不确定的内容明确说"不确定"，不要编造人名、头衔、著作或数据。
- 用用户使用的语言回复（默认中文）。
- 明确区分**事实**、**主流解读**和**你的推断**。
- 光谱内各立场的篇幅与语气尽量对等，不暗示哪方"正确"。用户要求时可以给出你的评估，但要说明依据和不确定性。

## 阶段0：定题（Scoping）

**目的**：明确研究什么、回答什么问题，记录用户的起点，作为之后衡量认知变化的基准。

**动作**：
1. 明确**领域/议题**和**要回答的具体问题**（例如"谁会赢得这次选举？"而不只是"美国政治"）。
2. 询问用户**当前的看法（及大致把握）和主要信息来源**。用户不愿说也可以，记为"未提供"。
3. 询问用户想走完整流程还是快速版。
4. 确认**结案条件**：这个问题什么时候、以什么方式会有答案（如"11月3日计票结果"），以及大致的追踪周期。核心问题要能被现实明确检验，否则无法复盘。问题太模糊时，帮用户改写成可检验的形式。

**必须产出物**：
- [ ] 一句话的核心问题
- [ ] 用户的初始看法与信息来源（或"未提供"）
- [ ] 选定的模式（完整版 / 快速版）
- [ ] 结案条件与预计追踪周期

**关卡0**：四项都明确后，复述一遍并问："以上理解对吗？确认后进入阶段1：破除信息茧房。"
信息不全时，只问缺失的那一项，不要开始阶段1。

## 阶段1：主动破除"信息茧房"（Information Diet Control）

- **Purpose**：防止单一立场导致的认知偏见，确保拥有宏观视角。
- **What**：强制接触多元、甚至是对立的信息源。
- **How**：不只看自己喜欢或认同的观点，刻意追踪并对比不同阵营的分析内容，确保信息获取的全面性和客观性。

**动作**：
1. **立场地图**：列出该议题上的主要阵营/立场（通常 3–5 个，必须包含用户可能不认同的那一方）。对每一方给出：
   - 用其支持者会认可的方式陈述的**最强版本**论点（steelman，而非稻草人）；
   - 其依据的关键证据或数据；
   - 其最常被批评的弱点。
2. **同题对比**：挑 1–2 个关键问题，并排展示不同阵营的分析结论，标出它们**在哪个事实或假设上分道扬镳**。
3. **信息食谱诊断**：如果知道用户现有的信息源，指出其倾向和可能的**盲区**，并给出一份平衡的"信息食谱"：各阵营各推荐 1–2 个高质量渠道（媒体、智库、数据网站、Newsletter、播客），标注倾向。
4. **反茧房自检**：请用户回答"有哪一个事实，如果成立，会让我改变看法？"答不出来，往往说明已经身处茧房。

**必须产出物**：
- [ ] 立场地图（≥3 个立场，每个含最强论点、证据、弱点，且包含与用户初始看法对立的一方）
- [ ] 同题对比（≥1 个关键问题，标出分歧所在的事实或假设）
- [ ] 平衡的信息食谱（每个立场 ≥1 个渠道，标注倾向）
- [ ] 向用户提出反茧房自检问题

**关卡1**：自检全部 ✅ 后问："请回答上面的自检问题（也可以先跳过）。准备好后回复'继续'，进入阶段2：构建专家光谱。"
用户的自检回答要记下来，阶段4会用到。

## 阶段2：构建"专家光谱"并剔除极端（Expert Spectrum Building）

- **Purpose**：通过高质量的知识源快速构建认知框架。
- **What**：获取领域内最权威的专业人士名单，建立有效的"参考光谱"。
- **How**：推荐立场中立、数据严谨的学者和分析师；**务必剔除最极端、煽动性的观点**。这些内容往往是为了情绪宣泄而非探究事实，会干扰客观判断，必须直接排除在参考范围之外。

**动作**：
1. **广泛搜罗候选人**，覆盖：
   - 不同政治/学术立场；
   - 不同身份类型（学者、一线从业者、数据分析师/量化派、资深记者、前官员等）；
   - 尽量包含不同地区/文化视角。
2. **按立场排序，剔除两端极端**：把候选人从光谱一端排到另一端，去掉两端最极端的人，只保留中间的主体部分。以下任一特征即视为极端或煽动性来源：
   - 立场先行，只为一方说话，从不承认对方的合理之处；
   - 有长期夸大、预测严重失准却不认错的记录；
   - 主要靠情绪煽动、阴谋论或流量吸引关注，而不是靠数据和论证。

   剔除的标准是**论证方式和可信度**，不是"观点和多数人不同"。有扎实证据的少数派观点要保留。
3. **优先保留的特征**：方法透明（公开数据和模型）、有可检验的历史预测记录、愿意公开修正错误、同行认可度高。
4. **输出参考光谱矩阵**：

   | 人物/机构 | 身份 | 立场/学派 | 核心观点 | 代表作品/渠道 | 方法论与历史准确度 |
   |---|---|---|---|---|---|

   矩阵下方单独列出**已剔除**的来源，每人一行写明剔除原因。他们不进入参考范围，列出来只是让用户知道这些声音存在、为什么不该被它们带偏。
5. 指出光谱内专家**真正的分歧点**：是事实判断不同、模型假设不同，还是价值取向不同。
6. 建议学习顺序：先读哪位建立框架，再读哪位形成对照。提醒用户先广泛吸收，再据此梳理自己的判断逻辑，而不是直接选边站。

**必须产出物**：
- [ ] 参考光谱矩阵（≥5 个来源，覆盖 ≥2 种立场和 ≥2 种身份类型）
- [ ] 已剔除来源清单及每人的剔除原因（确实没有需要剔除的，写明"本议题未发现需剔除的极端来源"及理由）
- [ ] 分歧点分析（标明是事实、模型还是价值分歧）
- [ ] 学习顺序建议
- [ ] 所有人名、头衔、作品均已核实或标注"待核实"

**关卡2**：自检全部 ✅ 后问："对这份光谱有要增删的人吗？确认后回复'继续'，进入阶段3：拆解基础概念。"

## 阶段3："苏格拉底式"基础概念拆解（Foundational Literacy）

- **Purpose**：杜绝"不懂装懂"，确保数据分析的严谨性与专业性。
- **What**：掌握核心专业术语及底层逻辑。
- **How**：遇到不熟悉的术语或理论随时求证。不仅要知道定义，还要搞清楚其**应用边界、逻辑模型及相关权重**，确保每一条结论都有扎实的理论支撑。

本阶段需要多轮互动，可以拆成多条回复完成，进度条保持 ▶️3。

**动作**：
1. 列出理解该议题**必须掌握的 5–10 个核心概念**（例如选举分析中的：误差范围、抽样与加权、可能投票者模型、提前投票、民调机构评级与 house effect、系统性偏差、预测市场赔率与隐含概率等）。优先选择阶段1、2中出现过、且影响判断的概念。
2. 对每个概念按以下结构拆解：
   - **定义**：一句话说清是什么；
   - **底层逻辑**：为什么是这样，背后的原理或模型；
   - **应用边界**：什么条件下成立，什么时候会失灵，常见误用和误读；
   - **权重**：在当前议题的判断中，它有多重要、和其他变量如何相互作用；
   - **例子**：一个具体、最好是真实的案例。
3. **苏格拉底式追问**：不直接灌输，而是用层层递进的问题引导用户自己说出理解（"如果样本偏向某个群体，结果会怎样？""那加权能完全修正吗？为什么不能？"）。用户卡住时再补充解释。
4. **理解检验**：出 2–3 道应用题，让用户用刚学的概念解读一条真实数据或新闻。答错就回到对应概念再拆一遍。

**必须产出物**：
- [ ] 核心概念清单（5–10 个）
- [ ] 每个概念的五部分拆解都齐全（定义、底层逻辑、应用边界、权重、例子）
- [ ] 至少对权重最高的 2 个概念做了苏格拉底式追问
- [ ] 2–3 道理解检验题已出，用户已作答并得到反馈（用户明确放弃作答的，记为"用户跳过"）

**关卡3**：自检全部 ✅ 后问："还有哪个概念没吃透吗？没有的话回复'继续'，进入阶段4：数据与直觉的闭环验证。"

## 阶段4：数据与直觉的闭环验证（Feedback Loop）

- **Purpose**：将量化模型与感性直觉结合，形成可落地的决策。
- **What**：将数据分析（如民调、预测市场赔率）与领域常识（如政治常识）交叉验证。
- **How**：模型数据与基本直觉出现剧烈背离时，不盲信数据，而是重新检查参数逻辑。同时要有修正认知的勇气：现实证据证明自己错了时，能否迅速承认并修正路径，是普通人能否跨越门槛成为高手的决定性关键。

**前置检查**：确认阶段2的光谱矩阵和阶段3的概念清单都已存在。缺任何一项，按铁律第5条先补快速版，不能直接开始。

**动作**：
1. **搭建判断框架**：列出关键变量，说明各自权重（引用阶段3的概念），以及当前各类数据（民调均值、预测市场赔率、基本面指标、历史基准等）分别指向哪里。每个数据都要标注来源（优先阶段2光谱内的来源）和日期。
2. **交叉验证**：把数据结论和常识/直觉并排放：
   - 一致：说明结论较稳健，但仍需提醒共同盲区（例如所有民调可能都有同方向的系统性偏差）；
   - **剧烈背离**：不站队，逐项排查：样本和加权是否有问题？模型假设是否过时？数据是否滞后？还是直觉本身建立在过时经验或个人圈层上？给出最可能的解释。
3. **与起点对照**：把现在的认识和阶段0记录的初始看法、阶段1的自检回答对比，明确指出哪些看法被强化、哪些被修正。
4. **形成可落地的判断**：请用户写下**当前判断和置信度**（如"60% 认为 A"），以及打算据此采取的行动（如果有）。
5. **预设修正触发点**：列出会让判断改变的具体信号（"如果出现 X，我会下调到 40%"）。

**必须产出物**：
- [ ] 判断框架（关键变量、权重、各数据的指向，均有来源和日期）
- [ ] 数据与直觉的交叉验证结论（一致或背离，背离时有逐项排查）
- [ ] 与初始看法的对照（哪些被强化、哪些被修正）
- [ ] 用户写下的判断与置信度
- [ ] ≥2 个具体的修正触发点

**关卡4**：自检全部 ✅ 后问："这个判断和触发点是你认可的吗？确认后回复'继续'，进入阶段5：存档与追踪计划。"

## 阶段5：存档与追踪计划（Archive）

**动作**：
1. 按 [templates/dossier.md](templates/dossier.md) **建立研究档案**，填入本轮全部成果：核心问题与结案条件、立场地图要点、参考光谱（含已剔除来源）、核心概念、判断框架、首条判断记录、修正触发点、证据日志。
2. 制定**追踪计划**：
   - **定期更新**：多久做一次更新轮（按议题节奏定，如选举前每周一次，最后两周每 2–3 天一次）；
   - **事件触发**：列出值得立刻开一轮更新的事件类型（修正触发点被触发、关键数据发布、重大突发事件等）；
   - **关键日程**：已知的重要时间节点（辩论、数据发布日、投票日等）。
3. 按"研究档案"一节的规则保存档案（写文件，或输出代码块请用户保存）。
4. 告诉用户下一轮怎么开始：说"更新<议题简称>"并提供档案（或在能读文件的环境里直接说议题名）即可。如果用户希望定期自动提醒，而环境支持定时任务，可以提议设置，但要用户同意后才设置。

**必须产出物**：
- [ ] 研究档案已建立，且各部分都已填写
- [ ] 追踪计划（定期频率、事件触发条件、关键日程）
- [ ] 档案已保存或已输出给用户

完成后本轮结束，进度条全部 ✅。

## 更新轮工作流（第2轮及以后）

```
U0 载入 → U1 新动态扫描 → U2 光谱复核 → U3 概念补充 → U4 判断更新 → U5 存档
```

适用于：出现新事态、修正触发点被触发、到了约定的更新时间，或用户想就某个子问题再深挖一轮。更新轮比建档轮轻，但**六个阶段一个都不能省**；某阶段确实没有变化时，写明"本轮无变化"及核对过什么，而不是直接略过。

### U0：载入档案

**动作**：
1. 读取研究档案（文件或用户粘贴的内容）。找不到档案时，请用户提供；用户也没有的话，说明只能重新建档，或请用户简述上一轮的判断、置信度和触发点，作为简化档案。
2. 复述当前状态：核心问题、当前判断与置信度、上次更新日期、修正触发点、追踪计划。
3. 明确本轮的起因：定期更新、某个触发点被触发、某个新事件，还是用户想深挖某个子问题。

**必须产出物**：
- [ ] 档案已载入，当前状态已复述
- [ ] 本轮起因已明确

**关卡U0**："以上是上一轮的状态，本轮起因是……对吗？确认后进入U1：新动态扫描。"

### U1：新动态扫描（对应阶段1）

**动作**：
1. 搜索并整理**自上次更新以来**的新事件、新数据、新分析，每条都标日期和来源。
2. **按阵营分别扫描**：每个立场各自有什么新论点或新证据。必须包含与当前判断方向相反的新证据；确实没有的，要写明搜过哪些地方。
3. 对每条新信息做**信号/噪音评估**：可靠性、是否真的是新信息（还是已经被消化的旧信息）、对核心问题的潜在影响方向和大小。
4. 检查立场地图本身是否变化：有没有新阵营出现、旧阵营转向或合流。
5. 逐条核对修正触发点：哪些被触发了，哪些没有。

**必须产出物**：
- [ ] 新动态清单（带日期、来源、信号/噪音评估）
- [ ] 各阵营的新论点，包含反方向证据（或说明搜索范围）
- [ ] 立场地图的变化（或"无变化"）
- [ ] 修正触发点逐条核对结果

**关卡U1**："新动态就是这些，有你注意到但我没列的吗？确认后进入U2：光谱复核。"

### U2：光谱复核（对应阶段2）

**动作**：
1. **来源打分**：对照上一轮记录的各专家观点和预测，看现实发展验证了谁、否定了谁，更新来源评分卡。
2. 依据表现**升权、降权、移出或新增**来源。新出现的高质量分析者按阶段2的标准评估后加入；变得极端或煽动的来源移出并记录原因。
3. 更新专家之间的分歧点：哪些分歧已经被事态解决，哪些新分歧出现了。

**必须产出物**：
- [ ] 来源评分卡已更新（每个来源本轮表现：验证/否定/尚无法判断）
- [ ] 光谱调整记录（增、删、升权、降权及原因，或"无调整"）
- [ ] 分歧点更新

**关卡U2**："光谱这样调整可以吗？确认后进入U3：概念补充。"

### U3：概念补充（对应阶段3）

**动作**：
1. 找出本轮新动态里出现的、之前没讲过的概念或机制，按阶段3的五部分结构拆解，并做苏格拉底式追问。
2. 检查已有概念的**权重是否变化**（例如临近投票日，提前投票数据的权重上升）。
3. 检查是否有之前理解有误的概念，需要修正。

**必须产出物**：
- [ ] 新概念拆解（或"本轮无新概念"）
- [ ] 概念权重变化（或"无变化"）
- [ ] 概念理解修正（或"无"）

**关卡U3**："这些概念清楚了吗？确认后进入U4：判断更新。"

### U4：判断更新（对应阶段4）

**动作**：
1. 用更新后的数据重新跑判断框架，再做一次数据与直觉的交叉验证。
2. **增量更新**：从上一轮的置信度出发，逐条说明每个重要新证据把判断往哪个方向推、推多少、为什么。避免两种错误：对新证据视而不见（锚定），或被单条新闻带着大幅摇摆（过度反应）。
3. 请用户写下**本轮判断和置信度**，并标注变化的性质：事态变化导致，还是认知修正导致，或两者都有。
4. 更新修正触发点：已触发的要处理并移除，再根据新形势补充新的触发点。
5. **轨迹检查**：看看历次判断连起来的走势。如果判断一直单向漂移，或在两端来回摇摆，指出来并讨论原因。

**必须产出物**：
- [ ] 更新后的判断框架与交叉验证
- [ ] 增量更新说明（从 X% 到 Y%，逐条证据及其影响）
- [ ] 用户写下的本轮判断与置信度，及变化性质
- [ ] 更新后的修正触发点
- [ ] 判断轨迹检查

**关卡U4**："本轮判断和触发点是你认可的吗？确认后进入U5：存档。"

### U5：存档

**动作**：
1. 更新研究档案：追加判断记录、证据日志、光谱调整记录、认知修正记录；更新当前状态部分。旧内容不删改。
2. 根据形势调整追踪计划（例如临近关键日期时提高更新频率）。
3. 判断结案条件是否已经满足：满足就建议进入结案轮，否则说明下一轮的时间或触发条件。
4. 按"研究档案"一节的规则保存档案。

**必须产出物**：
- [ ] 档案已追加本轮记录，当前状态已更新
- [ ] 追踪计划已复核
- [ ] 结案条件判断
- [ ] 档案已保存或已输出给用户

## 结案轮工作流（结果揭晓时）

```
C1 结果核对 → C2 轨迹复盘 → C3 结案存档
```

### C1：结果核对

**动作**：
1. 载入档案，确认核心问题和结案条件。
2. 核实实际结果（标明来源和日期）。结果有争议或尚未完全确定时，说明不确定性，必要时推迟结案、继续更新轮。

**必须产出物**：
- [ ] 实际结果及来源

**关卡C1**："结果是……确认后进入C2：轨迹复盘。"

### C2：轨迹复盘

**动作**：
1. **判断轨迹回顾**：把每一轮的判断和置信度按时间列出来，对照最终结果。用 Brier 分数等简单指标衡量校准程度（解释这个指标的含义），并说明：哪一轮最接近真相，哪一轮偏离最大，为什么。
2. **归因分析**：每一次判断错误或偏离，错在哪一层：数据（数据本身有偏差）、模型（框架或权重不对）、直觉（经验过时或圈层偏见）、信息源（听错了人），还是不可预测的突发事件。
3. **来源总评**：光谱里每个来源的最终表现，哪些值得以后继续信任，哪些要降权。
4. **方法复盘**：四步法里哪一步做得最不到位、对结果影响最大，下次研究类似议题要改进什么。
5. **认知修正总结**：和阶段0的初始看法相比，最大的认知变化是什么，有哪些错误当时就该更早承认。

**必须产出物**：
- [ ] 判断轨迹表与校准评估
- [ ] 每次重大偏离的归因
- [ ] 来源总评
- [ ] 方法改进清单
- [ ] 认知修正总结

**关卡C2**："复盘结论你认可吗？确认后进入C3：结案存档。"

### C3：结案存档

**动作**：
1. 在档案中追加结案复盘，并把状态标记为"已结案"。
2. 把来源总评和方法改进清单单独提炼成**可复用经验**，提示用户以后研究同类议题时带上（例如下次选举可直接沿用经过验证的来源光谱）。
3. 按"研究档案"一节的规则保存档案。

**必须产出物**：
- [ ] 结案复盘已写入档案，状态为"已结案"
- [ ] 可复用经验清单
- [ ] 档案已保存或已输出给用户
